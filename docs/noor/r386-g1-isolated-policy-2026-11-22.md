1. **Late replay and durable receipts:** do not purge or expire any existing receipt while request IDs can be retried indefinitely. Existing candidate receipt retention is end-of-calendar-range. G1's `g1-retention-lock.sql` denies `expire_receipts` unconditionally in the synthetic candidate. The original S1 fixture is retained intact, then the new guard is layered afterwards. A future bounded-window change needs a separate monotonic reject-old-ID scheme, owner-scoped migration, and explicit approval.
2. **HMAC versioned key custody:** retain every key referenced by a surviving receipt. The isolated trusted-server key-inventory callback supplies historical receipt key IDs, and `verifyG1HistoricalKeyCoverage` rejects missing historical keys and more than eight keys (the limit of the existing receipt bridge). Rotate only after approved archival/rotation proof; no secret material in logs or code.
3. **Account lifecycle:** administrative disable/soft delete means revoke NOOR sessions and grants, disable Auth/linkage, retain personal data. Irreversible erasure is a distinct privileged operation. Require confirmed erasure of authoritative operational state, candidate owner-owned events, delivery, analytics and receipts, and separate source/journal/storage controls where applicable. Minimal evidence proves erasure without leaking content. Deleted owner IDs must never be reassigned. Current R316 admin delete explicitly returns `personalDataRetained:true` and is NOT permanent erasure.
4. **Transaction owner authority:** only a trusted server-side verified NOOR session determines `ownerId`; verify it is active, unrevoked, within lifetime, authorized for `noor-personal`, un-erased and non-reassigned. Never accept a browser-supplied owner or privileged SQL role. The isolated wrapper and synthetic tests do NOT establish a managed Auth-to-RLS transaction proof.
5. **Privacy and provenance:** no journal narrative, finance, student, or wellbeing content in analytics by default. Preserve unknown historical completion dates/weights as unknown, not inferred. V1 event contract remains strict; unknown versions fail closed. Source operational JSONB and existing scores remain authoritative.
